# Audit prompt

The prompt below has your agent check your repo and your user-level agent config against the
practice cards in [`INDEX.md`](../INDEX.md). It proposes fixes and, in a full run, applies the
ones you agree to, one at a time. It ends with a watch list: the talks and pages behind the cards
you are missing.

**Which agents:**

- **Claude Code on a paid plan or an API key, and OpenAI Codex CLI on any plan, the free one
  included:** the full audit, changes included. These two were checked on the kit's seeded test
  repo.
- **Any other agent that can run shell commands, read files and fetch a web page** (on a paid
  plan, an API key or a free quota), **and Claude Code on a free plan:** the audit runs read-only. You get the verdicts, the
  proposed fixes as a list to apply by hand, and the watch list; nothing in your setup changes.
- **Testers.** On such an agent you can choose to be a tester: then the audit also applies the
  changes you agree to, the same way, after your agent names its config files and backs up the
  user-level ones. The kit has not been checked on your agent, so a file your agent fails to
  name is not in the backup and the undo cannot put it back. At the end you get a short tester
  report; [send it to us](https://github.com/Osasuwu/ai-dev-kit/issues/new?template=audit-tester-report.yml)
  so the kit can support your agent properly.
- **An agent that cannot run commands, or no agent yet:** use the interview prompt instead, in
  [English](interview.en.md) or [Russian](interview.ru.md).

The audit takes many turns. On a free quota, check the remaining limit first (`/status` in
Codex). The maintainer's audit of the kit's small test repo used 13% of a free Codex quota (which
limit window was not recorded), and a larger repo takes more. A read-only run in Antigravity, on a
Gemini model with a Google AI Pro plan, used 4% of the 5-hour limit. A run the quota cuts off
leaves at most one change in progress. Discard that one by hand (`git restore` on the audit branch, or copy
the file back from its `before-<N>` folder), and the undo commands the audit gave you before its
first change put back the rest.

**Running it again:** at the end the audit offers to save a short result file outside the repo
(the date, each card's verdict, the fixes you declined). Paste the prompt again later, from this
page so you get its latest version, and give your agent that file: it tells you what changed
since, new cards included, and does not propose a fix you declined unless you ask. The prompt's
first line is its version; your agent compares it with the latest one and tells you if your copy
is not the latest.

**Several repos:** if you have more than one repo and their agent setup is not kept in sync, the
audit can check the others in the same run, by paths you give it. Your user-level config is
checked once, each repo's own config separately, and you get a table of which cards hold in which
repo, with a fix for one repo modelled on another where the card already holds. You get one watch
list for all of them. It changes files only in the repo you started it in; fixes for the others go
on the list for you to do by hand, or you run the audit there. Each extra repo uses more of your
quota; how much has not been measured yet.

**What it may change:**

- In the repo: only files git tracks, or new files, only on a new branch, `ai-dev-kit/audit-<date>`,
  committed locally. A fix to a file git ignores, such as `.claude/settings.local.json`, is yours
  to make. It never touches your default branch, never pushes, opens no pull request
  and writes no repo or GitHub setting: a fix like that goes on a list for you to do by hand.
- In any file your agent loads as rules, permissions, tools or servers, at user level or in the
  repo: only the kinds of change listed in step 5 of the prompt. No hooks: the kit ships no
  hook scripts for you to install yet.
- Before its first change it copies the user-level files it may touch (in a tester run, every
  user-level config file it named) to a backup folder and
  opens the audit branch, then shows you how to undo everything without the agent (a restore
  command, the branch's undo commands, or both). It changes nothing without your yes to that one
  change.
- Outside these, only the result file, in a folder of its own, and only on your yes.

**How to use it:** open your agent in the repo you want to check (with several repos, the one you
want fixes applied in), and paste the whole block
below. Read it first: it is what your agent will follow.

If the result did not help, [say what was missing](https://github.com/Osasuwu/ai-dev-kit/issues/new?template=base-not-enough.yml).
This repo and its issues are public: describe in your own words, and do not paste code or paths
from a private repo.
