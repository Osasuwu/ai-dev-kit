# data/

The public data layer behind the kit: ideas from 911 AI Engineer conference talks (the 2026
events, plus talks listed with no event), as claims grouped into clusters. It is derived work; where it comes from and how to fetch the
sources again is in [`sources.md`](sources.md), and how it is regenerated is in
[`pipeline/README.md`](pipeline/README.md).

## Files

Each file carries exactly the fields below. [`pipeline/check_data.py`](pipeline/check_data.py)
checks every file against them and fails on any other field, on a file with no schema, and on
a reference to the maintainer's private material; `tests/test_data_pipeline.py` runs it on
this directory.

| File | Records | Fields |
|---|---|---|
| `claims.jsonl` | 2118 claims | `cid`, `talk`, `claim`, `kind`, `evidence`, `depth`, `area`, `search`, `quality`, `pitch` |
| `talks.jsonl` | 911 talks | `id`, `gist`, `quality`, `pitch`, `audience` |
| `clusters/A.json` … `F.json` | 386 clusters in six groups | `clusters` (`key`, `title`, `idea`, `contested`, `cids`), `singletons`, `noise` |
| `merge-map.json` | 48 joins | `merged` (`key`, `title`, `idea`, `contested`, `from`) |
| `cluster-index.tsv` | 298 clusters | `key`, `talks`, `title`, `idea` |

- A claim is one transferable idea from a talk, in the extraction step's words. `talk` is the
  talk's id. `kind`, `evidence` and `depth` grade the claim; `quality` and `pitch` are its
  talk's grades; `search` is a phrase for finding the passage in the transcript.
- A talk record holds the extraction step's own `gist` and grades, nothing from the
  conference site beyond the id. A gist names no speaker ("the speaker", "a <company>
  speaker"); speakers' names were removed from the first export's gists.
- A cluster groups claims, by `cids`, that carry the same idea. The groups `A`–`F` were
  clustered apart; `merge-map.json` joins clusters across groups under `M-` keys.
- `cluster-index.tsv` is generated by `pipeline/build_index.py`: every cluster, after the
  joins, whose claims come from two talks or more, most talks first.

Claim ids are stable: a rerun keeps every published id and numbers new claims after the
highest (`pipeline/merge_claims.py`).

## What is not here

- Everything fetched from the conference site: titles, URLs, events, durations, speakers,
  summaries, slide text, transcripts, chapters and citations (`sources.md` says how to fetch
  them again).
- The maintainer's own layer: per-cluster status, relevance and depth tier, which were judged
  against the maintainer's projects and notes; the picks, open problems and written sections
  built on them; the Russian cluster titles, written in that same step; the maintainer's
  backlog, digest state and notes.
- Outputs of outside-source probes (forum threads, vendor guides matched against the
  clusters): not part of this layer.
